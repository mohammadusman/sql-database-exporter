# Security policy

## Supported versions

This repository does not publish versioned releases yet. Security fixes should be made against the current source on the default branch.

## Reporting a vulnerability

A private vulnerability-reporting contact is not configured for this project.

Before inviting reports, the maintainer should enable GitHub private vulnerability reporting, where it is available for the repository, or publish a monitored contact method in this file. This document does not claim that private reporting is already turned on.

Until a private channel exists:

- Do not open a public issue that includes exploit details, credentials, connection strings, or data exported from a database.
- Do not send secrets to an address guessed from a commit, profile, or document.

After a private channel exists, describe the behavior, the affected script version or commit, and the conditions required to reproduce it. Omit passwords, connection strings, and exported records.

## What helps a report

- The PowerShell edition and version.
- Whether the problem is in connection handling, file output, logging, or dependency use.
- A sanitized error message. Remove host names, database names, user names, and any row data before sharing it.

There is no bug-bounty or response-time commitment.
